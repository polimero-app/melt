# Configuration and credentials

Last-updated: 2026-10-18

The CLI and desktop read the same printer/camera configuration. They store
passwords and TLS pins separately in the OS keychain, under service `melt`.

## Locations and files

| Platform | Default configuration directory |
| --- | --- |
| Linux/other Unix | `$XDG_CONFIG_HOME/melt`, or `$HOME/.config/melt` when unset |
| macOS | `$HOME/Library/Application Support/melt` |
| Windows | `%APPDATA%\melt` |

A non-empty `MELT_CONFIG_DIR` overrides the complete directory for profiles,
preferences and the desktop status snapshot. It does not isolate the OS
keychain or the Tauri webview's local storage.

| File/store | Contents |
| --- | --- |
| `melt.yaml` | Printer profiles, optional independent camera and smart plug profiles, printer-camera links |
| `melt-preferences.yaml` | Notifications, slicers, last library folder, public firmware catalogue opt-in |
| `melt-status-cache.json` | Last desktop monitoring payload for initial display; not configuration |
| OS keychain | Printer access codes/API keys, Bambu TLS pins, camera and smart plug passwords |
| Webview local storage | Theme, language, active view/printer and temperature presets |

Missing profile/preference files produce empty/default settings. Unsupported
schema versions and malformed profiles are refused. Profile and preference
writes use a temporary file and atomic replacement, and reject an external
change since the file was read. Unix configuration directories are restricted
to `0700`, and profile/preference files to `0600`.

## Printer and camera schema

Use the UI or CLI to create profiles so connection verification and keychain
writes stay coordinated. This is a sanitized schema example, not a working
credential setup:

```yaml
version: 2
profiles:
  workshop:
    driver: bambu-lan
    host: 192.0.2.10
    serial: SANITIZED_SERIAL
    model: H2C
    timeout: 10s
    insecure: false
    created: '2026-10-12T12:00:00Z'
    updated: '2026-10-12T12:00:00Z'
cameras:
  porch:
    id: '0123456789abcdef0123456789abcdef'
    driver: tapo
    host: 192.0.2.20
    username: melt
    rtsp_port: 554
    timeout: 10s
    created: '2026-10-12T12:00:00Z'
    updated: '2026-10-12T12:00:00Z'
printer_cameras:
  workshop:
    cameras: ['0123456789abcdef0123456789abcdef']
    selected: '0123456789abcdef0123456789abcdef'
```

Readers accept schema versions 1 and 2. Saves use version 2 only while camera
profiles or link records exist, and otherwise write version 1. Camera IDs are
immutable, unique 32-character lowercase hexadecimal values generated by
Melt. Links reference IDs, so a rename preserves the password and selection.
Invalid IDs, duplicate/dangling links and a selection outside the linked set
are rejected. Camera sections in version 1 are also rejected.

A missing selection means built-in camera. Unlinking or removing a selected
camera restores that default. Removing a printer drops its links and printer
secrets but preserves independent camera profiles. Renaming a printer in the
desktop moves its links. The CLI has no `printer edit` command; camera editing
is available on both surfaces.

## Smart plug schema

Plug profiles add schema version 3. Saves use version 3 only while plug
profiles exist, otherwise 2 while camera data exists, otherwise 1. Readers
accept versions 1 to 3. Plug IDs are immutable 32-character lowercase
hexadecimal values, like camera IDs. See [smart plugs](smart-plugs.md).

```yaml
version: 3
plugs:
  bench-power:
    id: '11111111111111111111111111111111'
    driver: tapo
    host: 192.0.2.30
    username: operator@example.invalid
    timeout: 10s
    printers: [workshop]
    cameras: ['0123456789abcdef0123456789abcdef']
    created: '2026-10-18T12:00:00Z'
    updated: '2026-10-18T12:00:00Z'
```

`printers` holds printer names, because printers have no stable ID. `cameras`
holds camera IDs. The username keeps its case. Model, hardware and firmware
are observed, never stored. Renaming a printer rewrites its name in every
plug; removing a printer or camera drops it from every plug, and removing a
plug drops its links. None of these operations switches a relay.

## Preferences and appearance

The preferences file remains schema version 1 and uses camelCase keys:

```yaml
version: 1
notifications:
  completion: true
  failure: true
  disconnection: true
slicers: []
libraryPath: null
publicFirmwareCatalogue: false
```

Notifications default on. Slicer records contain `name`, executable `path`
and `enabled`; saved choices merge with locally detected slicer applications.
`libraryPath` remembers the last browsed folder. On first use, the desktop
creates a `Melt` folder in the user's Documents directory.

The public firmware source defaults off. Enabling it permits bounded HTTPS
requests to official model pages; the firmware screen's one-shot check does
not change the saved preference. Theme (`system`, `light`, `dark`), locale
(`en`, `pt-BR`) and material temperature presets belong to the webview rather
than this YAML file. See [desktop usage](desktop.md).

## Keychain and transport security

| Keychain account | Value |
| --- | --- |
| `<driver>:<printer-name>:access-code` | Bambu LAN access code or optional Moonraker API key |
| `bambu-lan:<printer-name>:tls-fingerprint` | Pinned certificate SHA-256 identity |
| `camera:<immutable-id>:password` | Local Camera Account password |
| `plug:<immutable-id>:password` | TP-Link account password for a smart plug |

Linux uses Secret Service; macOS and Windows use their native keychain
backends. Authenticated operations need access to that user's credential
store. A trusted-LAN Moonraker setup can work keylessly; setting
`MELT_CONFIG_DIR` alone does not make Bambu/camera credentials available to a
different user, machine, container or session.

Secure Bambu first contact checks the certificate common name against the
configured physical serial. Later connections enforce that identity and the
stored pin. A mismatch fails instead of silently changing the pin or endpoint.
Refresh the pin explicitly after verifying a legitimate certificate change.
Discovery and live address suggestions never rewrite the profile.

Tapo uses plain RTSP on the LAN with Digest authentication, not encrypted
video. Basic-only authentication is rejected. Only the password is secret;
the local username, host and profile name remain in configuration. Bambu
signing-required or conflicting authorization evidence can leave a configured
printer read-only even when its credentials and pin are valid.

## Backup, recovery and downgrade

Back up profile/preference files together with an appropriate backup of the
user's keychain. YAML alone cannot restore credentials. The files contain
network addresses, usernames and physical printer serials, so sanitize them
before sharing. The status snapshot may also contain local operational data;
use the desktop's redacted diagnostics export for support.

If an external edit causes a concurrent-update error, reload the profiles or
preferences before retrying. An unavailable/missing keychain secret requires
restoring credentials or re-verifying the profile; it is not repaired by
changing the schema or disabling TLS.

Before running a version-1-only Melt build, remove all cameras with the current
CLI/desktop and save; the remaining printer-only file is written as version 1.
For a manual downgrade, close Melt, back up `melt.yaml`, remove `cameras` and
`printer_cameras`, and set `version: 1`. Remove orphaned
`camera:<id>:password` entries if they are no longer needed. Do not change only
the version number while retaining camera data.

To run a version-2 or older build after using smart plugs, remove the plugs
with the current CLI/desktop. Manually, back up `melt.yaml`, delete `plugs:`
and set `version` to 2 (cameras present) or 1, then delete the orphaned
`plug:<id>:password` entries. Do not change only the version number while
retaining plug data.
